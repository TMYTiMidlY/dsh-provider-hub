## 全量搜索的验收边界

- 两条查询、三路各 90 条，合计 540 个输入，经 URL 去重保留 535 条。
- 原生结果值、模型可见文本和展示 metadata 均保留最后一条来源；没有固定 8/200 条截断。
- 上游自身条数、响应大小和超时仍是实际边界；不宣称穷尽互联网。
- 显式保存的正数仍是主动上限，需要设为 0 才是全量。
- 历史日志不改写、不补搜；生图测试使用离线数据，不代表做过付费上游生图或真实浏览器视觉验收。

## 发布门槛

集成候选必须以同一份源码通过干净依赖安装、依赖检查、完整测试（不跳过）、打包检查和实际宿主 rc.2 回归。干净安装修复 `d87e72f` 已核对真实提交及成功的 GitHub Actions，但它验证的是原生图分支的 alpha.1 图；本集成保留其精确开发依赖、锁文件契约与 `npm ci` 流程，统一升级为账号池已经使用的 rc.2 图，并对最终候选重建锁、重新测试。不把原分支 222 项通过当作最终集成的通过结论。
